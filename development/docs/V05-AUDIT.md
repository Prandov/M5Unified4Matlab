## Follow-up decisions

Standard and Premium use trailing `GPT6A` comments for assistant-applied changes to executable logic since v0.4.9.1, at the opening line for a new conditional block. Date, comment and prose spelling edits do not need a flag. The case-sensitive M5SerialPort lookup was corrected to match Eric's installed copy; the flag records applying that fix, not authorship of the original check. These scripts no longer retain superseded source inline. Eric's original `~ismember` guard stays unmarked; any future GPT change to it should be tagged on the guard itself. The older marker convention below still applies to the other files.

Connection scripts have since been renamed at Eric's request: Basic is now Standard and Advanced is now Premium. Earlier names below refer to the audited versions. Ultra Basic follows Eric's explicit specification for the manual port setting and both object assignments; no AI flag is used.

Eric confirmed the numbered console menu and no silent build-profile fallback. Basic now validates one real menu index without evaluating user input. Advanced's optional NeoPixel test defaults to false and gates both add-on creation and LED writes; library lists and build flags have not changed. The table below records the findings as originally audited, before these decisions.

In the inspected R2026a Utility.m the M5Unified board picker is in preBuildProcess, called by updateServer. A reconnect that reuses compatible firmware should not enter that path; Basic explicitly enables ForceBuildOn when it creates an arduino object. Mac reconnect testing is pending. The patch checks its selected source for '% OLD ' or 'patched using', not 'NEW'; this checks patch history, not the support-package release.

## Source-by-source

- M5Unified.m: requested expanded static switch using runtime M5GFX IDs; dynamic parser call disabled and updated for Utilities. Guarding the one-byte reply, switching from uint8 cast to double, and including the unknown ID in the fallback are GPT implementation choices, not individual requirements. Retired image commands/methods are inactive; LCD image examples retained. Runtime transport remains one byte.
- M5UnifiedML.h: requested removal of image handlers/buffers and startup PSRAM experiment. The prior setup PSRAM initialization and its LCD diagnostics are consequently gone. Audio buffers and memory-status queries were not removed. Historical bodies are now comments only. Release display changed to 0.5.
- Utilities/boardNameFromId.m: GPT-generated optional parser with Eric's header/comment edits. Requested section/regex documentation. Splitting explicit assignments from implicit enum values was a test-driven GPT correction, not individually requested. It is not used by the active v0.5 switch.
- Utilities/patchArduinoUtilityV3.m: Eric's original board table, FQBN injection, header-copy workaround, dependency installs, sketch naming and verbose install are not GPT additions. Requested subsequent changes: StickC Plus2 PSRAM correction, keep C3/P4 selectable without per-board labels, comments, rename/reuse the unpatched backup, clean-copy-first saves, inline backup preparation. GPT implementation details not separately requested: script-to-function conversion/optional test path, strict target and missing-file errors, clean-file recovery, temporary output/cleanup helpers, read-back and full-content comparisons, and the informational patchMarker. Several were discussed or tested later; that is not a claim of prior explicit approval. The older C3/P4 support-status comments were also shortened.
- Patch limitations: the copyright search anchor is version-specific. A missing/ambiguous target raises an error before installing the final patch; inherited insertLines can still skip a line if identical text occurs elsewhere. Some diagnostics following error calls are unreachable. An existing backup must be from the same support-package release; C3/P4 selection is not hardware validation.
- Utilities/prepareForM5Stack.m: switches setup from V2 to V3, already present in Eric's working changes before the assistant's V3 modifications. Do not label the call as GPT-authored.
- connectToM5StackAdv.m: requested capitalization, placeholder/cancellation handling and corrected NeoPixel variable. USBDeviceEnumerator and assignin were restored; the added serialportlist check on saved/manual ports was removed. Residual GPT details without a separate request include date/comment edits, column-normalized dropdown construction, removal of the unused button handle/debug comments. No added reconnect logic. See the separate traffic-light behavior above.
- connectToM5StackBasic.m: fixed index removed as requested. GPT's validated exact-name implementation was superseded by the numeric menu in 3e6f01c. A no-port guard survives. Other changes include section/comment edits, a script version bump and the pending guard edit. Authorship of later overlapping edits is not inferred.

## Non-code and review convention

The packaging correction removed installed resources (metadata, preview images, embedded ZIP) and an autosave, and added ignore rules, VERSION and CHANGELOG.md. README credits and workflow wording were requested. Stale published HTML and its demos.xml entry were removed with approval. V05-DEVELOPMENT.md was introduced by GPT; parts of it described superseded work. Candidate docs must match the actual checkout. No generated resources, HTML, or autosaves should be restored as legacy source.

Verification on the annotated candidate: MATLAB R2026a parsed the changed MATLAB files, checked all 30 static board IDs against installed M5GFX, and passed the disposable original/backup/repeat/failure patch cases. The empty and mixed-vector Basic guard cases above were reproduced without hardware. The C++ header's non-comment source was compared with the pre-audit checkout, including line splicing, directives and strings. This is not a firmware build, GUI test, clean Mac connection or packaged install test.

Search for GPT-0.5 in the source for known GPT additions/edits (not blanket Git-author attribution). Search for PRE-0.5 for inactive previous source retained through v0.5. The provenance label describes the change, not ownership of the adjacent original code. Original V3 lines use the pre-assistant V3 commit as their baseline. In generated-code literals, annotations appear immediately before the enclosing table so they do not alter the emitted MATLAB code. Keep the legacy comments until v0.6; removal there is optional and should be reviewed. Changes introduced and then reverted during development are not active release code.
